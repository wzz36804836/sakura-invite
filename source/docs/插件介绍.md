# SakuraInvite · 樱花邀请系统

**版本：1.3.0｜适用：Paper 1.21.11｜运行环境：Java 21｜作者：Sakura_Girl**

SakuraInvite 是一个 Minecraft 服务端邀请插件。老玩家设置奖励并预存物品、金币，将个人邀请码分享给朋友；新人绑定后完成成长任务，即可获得这份奖励。服务器还可以给邀请人设置额外奖励，鼓励玩家带朋友一起游玩。

它也提供官方活动码，适合服务器开展开服福利、节日礼包和限量兑换活动。玩家无需安装客户端模组，进入服务器即可使用。当前版本不支持 Folia。

## 一、个人邀请怎么玩？

整个流程是：

**邀请人设置奖励 → 预存一份 → 分享邀请码 → 新人绑定并占用一份库存 → 完成任务 → 领取奖励。**

例如，小樱将每份新人奖励设置为 **3 个钻石 + 100 金币**：

1. 小樱创建个人邀请码，系统实际收取 3 个钻石和 100 金币，获得 1 份可用库存。
2. 小樱再补充两次，累计预存 9 个钻石和 300 金币，可供 3 名新人绑定。
3. 小明使用邀请码，系统立即为小明预留一份，剩余可用库存变为 2。
4. 小明完成分配的全部成长任务，获得 3 个钻石和 100 金币。
5. 如果服务器配置了邀请人奖励命令，小樱还会收到服务器提供的额外奖励。

**新人这份奖励由邀请人出资；邀请人的额外奖励由服务器配置的命令提供。** 插件不会因为创建了一个邀请码就无限生成个人奖励。

每名玩家只能拥有一个个人邀请码，也只能绑定一个个人邀请码。不能绑定自己的码。当前没有玩家自行解绑、更换邀请人或重新抽取任务的功能。

## 二、奖励怎么设置和管理？

输入 `/invite create` 打开奖励设置菜单。奖励可以是物品、金币，或两者组合，至少设置一种。

菜单里的物品是奖励模板，不是实际存放物品的箱子：

- 左键奖励格：复制光标物品；光标为空时复制主手物品。
- 右键奖励格：清空该格模板。
- 点击金锭：在聊天中输入每份金币金额。
- 确认前把光标上的物品放回背包，系统才会按模板实际扣取一份奖励。

实物必须放在背包主存储区，盔甲栏、副手和其他容器中的物品不参与扣取。金币最多支持两位小数。

创建后，每份奖励模板固定。使用 `/invite fund` 可以按原模板补充一份，使用 `/invite info` 可以查看模板、邀请码和剩余库存。

`/invite withdraw` 每次退回一份尚未被新人绑定占用的库存，退款进入自己的待领取列表。**已经预留给新人的奖励不能取回**，保证新人完成任务后仍有对应奖励。

## 三、新人需要完成什么任务？

新人使用 `/invite use <邀请码>` 绑定个人码后，默认获得 **3 个随机且不重复的成长任务**。服主可以调整任务数量和任务池。

插件附带 50 个默认任务，分为六类：

| 类型 | 任务举例 |
|---|---|
| 在线时间 | 累计在线 15 分钟、30 分钟 |
| 经验等级 | 经验等级达到 10 级、20 级 |
| 击杀生物 | 击杀 10 只僵尸、20 只骷髅 |
| 挖掘与采集 | 挖掘煤矿石、钻石矿石，砍伐原木 |
| 成熟作物收获 | 破坏并收获成熟小麦、胡萝卜等作物 |
| 钓鱼 | 成功钓鱼 5 次、10 次 |

玩家通过 `/invite gui` 查看任务和进度。全部任务完成后，系统生成待领取奖励，并在在线、背包空间等条件满足时自动尝试发放；也可以使用 `/invite claim` 手动触发领取。

有效邀请按新人完成全部任务计算。邀请人奖励命令如果暂时没有成功执行，不会改变已经完成任务的事实。

## 四、官方活动码有什么区别？

个人码用于“玩家邀请朋友”，官方码用于“服务器发福利”。

| 对比项 | 个人邀请码 | 官方活动码 |
|---|---|---|
| 创建者 | 有创建权限的玩家 | 管理员 |
| 奖励来源 | 邀请人实际预存 | 服务器提供，无须管理员预存 |
| 领取条件 | 绑定后完成成长任务 | 兑换已发布、未过期且有名额的码 |
| 数量控制 | 按预存份数提供绑定名额 | 可设置总领取名额 |
| 奖励内容 | 物品、金币 | 物品、金币、控制台命令 |

官方码先保存为草稿，管理员设置好奖励后再发布。可以限制总名额和有效时间，同一玩家不能重复领取同一个官方码。

例如，创建一个总共 100 个名额、有效 24 小时的活动码：

```text
/invite admin createofficial SAKURA2026
```

在菜单中设置奖励并保存，然后执行：

```text
/invite admin limits SAKURA2026 100 1440
/invite admin publish SAKURA2026
```

有效期从设置限制时起计算。玩家通过 `/invite use SAKURA2026` 兑换。官方码也使用持久化待领取机制，满背包时可以稍后再领。

## 五、邀请记录和排行榜

插件提供个人邀请记录与有效邀请排行榜，方便玩家查看自己带来了哪些朋友，以及哪些邀请已经完成任务。

- `/invite records`：显示最近 10 条邀请记录。
- `/invite top` 或 `/invite rank`：显示前 10 名，同分并列。
- `/invite info`：查看自己的邀请码、奖励模板和可用库存。

安装 PlaceholderAPI 后，可以把邀请码、邀请人、受邀人数、受邀名单、有效邀请数、排名及任务进度放到其他支持占位符的界面中。占位符数据约 5 秒刷新一次。

## 六、离线、满背包和异常情况怎么处理？

正常的离线或背包空间不足不会直接丢掉奖励。系统会保存待领取记录，等待条件满足后继续尝试发放，也不会把装不下的奖励直接扔在地上。

邀请人的命令奖励会等邀请人在线后执行。金币发放依赖经济服务；服务暂不可用时保留待领取记录。

预存和发奖都有持久化记录。如果服务器在实际扣款或发奖过程中崩溃，无法确定是否已经部分到账的操作会交给管理员核对。它不能保证第三方经济和控制台命令在所有故障下都严格只执行一次，因此不能对异常记录盲目重复发奖。

## 七、防刷和管理功能

插件提供以下限制和管理入口：

- 禁止个人码自绑，限制一名玩家只绑定一个个人码。
- 可限制同一邀请人来自同一 IP 的绑定数量，以及阻止与邀请人相同 IP 的绑定。
- 挖掘任务排除新版安装后由插件记录到的玩家放置方块，标记随区块保存。
- 作物任务按成熟作物被破坏时计数，反复种植本身不算完成。
- 菜单保护奖励展示物品，并检查创建权限、物品数量、余额和重复提交。
- 管理员可停用邀请码，查看并处理异常预存和发奖记录。

停用代码会阻止后续使用，但不会抹掉历史，也不会取消已经预留或已经进入待领取列表的奖励。

IP 限制和方块标记不能识别所有小号及其他插件改动世界的行为。当前也不支持多个服务端实例同时共享同一套插件数据库运行。

## 八、常用命令速查

| 命令 | 用途 |
|---|---|
| `/invite gui` | 打开邀请中心、查看任务 |
| `/invite create` | 创建个人码并预存一份奖励 |
| `/invite info` | 查看自己的邀请码与库存 |
| `/invite fund` | 补充一份固定模板奖励 |
| `/invite withdraw` | 退回一份未预留库存 |
| `/invite use <码>` | 绑定个人码或兑换官方码 |
| `/invite claim` | 尝试领取自己的待发奖励 |
| `/invite records` | 查看邀请记录 |
| `/invite top` | 查看排行榜 |
| `/invite admin official` | 打开官方码管理菜单 |
| `/invite admin deletecode <码>` | 停用代码并保留历史义务 |
| `/invite admin deliveries` | 查看需要核对的发奖记录 |
| `/invite admin funding` | 查看需要核对的预存记录 |
| `/invite reload` | 重载配置和任务；数据库连接变更需重启 |

主命令还可以写为 `/si` 或 `/sakurainvite`。普通玩家默认拥有创建、使用权限；管理和重载权限默认给予 OP，也可以通过权限插件分配。

## 九、安装要求与当前验证情况

将 `SakuraInvite-1.3.0.jar` 放入服务端 `plugins/` 目录启动即可。新安装默认使用 SQLite，不需要另外安装数据库；也可配置 MySQL。

| 组件 | 是否需要 |
|---|---|
| Paper 1.21.11、Java 21 | 必需 |
| Vault 和经济插件，例如 XConomy | 使用金币奖励时需要 |
| PlaceholderAPI | 展示占位符时按需安装 |
| CraftEngine | 按服务器自定义物品需求选用，需验证具体物品表现 |
| 点券等命令提供插件 | 奖励命令用到时需要 |

默认邀请人奖励配置含 `points give %player_name% 100`。服务器没有对应点券插件时，应换成实际可用的命令，或者把 `rewards.inviter-commands` 设置为 `[]`。

1.3.0 已构建成功，20 项回归测试通过。实际 Paper 玩家操作、真实 MySQL、Vault/XConomy 和 CraftEngine 联动尚未完成验证，正式开放前需在测试服走完一次创建、绑定、任务完成和领取流程。

从旧版本升级时，先停服并备份数据。旧个人码因为无法可靠推算剩余库存，不会自动获得可供新绑定的份数；邀请人补充奖励时，会优先填补旧版未预留、未结算的关系。详细升级步骤和管理员恢复命令见同目录的《SakuraInvite-1.3.0-使用与升级说明》。
