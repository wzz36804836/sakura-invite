# SakuraInvite 1.3.0 · 使用与升级说明

适用：**Paper 1.21.11 / Java 21**。客户端无需装模组。**不支持 Folia。**

## 这次改了什么

- 个人邀请码使用真正的有限库存：玩家预存一份物品/金币，绑定一名新人时预留一份。库存用完无法继续绑定，可补充。
- 奖励菜单显示模板复制品，确认时才从背包扣实物。保护 Shift、拖拽、数字键与连续提交等入口，创建权限在业务入口再次检查。
- 新增自己的邀请码详情、补充奖励、退回未预留库存、刷新任务和领取待发奖励。
- 奖励先写入数据库待领取列表。离线、背包放不下或经济服务暂不可用时保留，不再把溢出物品直接丢地上。
- 预存使用本地持久化日志及数据库操作编号，数据库重试不会重复增加库存。发放中断、无法判断是否到账的操作进入人工核对，避免盲目重发。
- 官方码先创建草稿，设置奖励后手动发布；可配置总名额和有效期。
- 金额只接受普通十进制，最多两位小数、上限 10 亿，拒绝科学计数法和超长输入。
- 数据库初始化完成后才开放功能；增加有界队列、进度合并、大小写统一唯一约束和数据库版本号。
- 修复受邀人名单占位符、统一同分排名，重排 Java 代码并加入回归测试。
- 挖矿任务排除插件记录到的玩家放置方块，标记随区块保存；`PLANT` 改为统计成熟作物收获，避免反复拆种直接刷任务。

## 安装和升级

**新安装：**将 `SakuraInvite-1.3.0.jar` 放入服务端 `plugins/`，启动后默认使用 SQLite。金币功能需要 Vault 与经济插件，例如 XConomy；仅物品奖励可不安装经济插件。PlaceholderAPI、CraftEngine 均按需要安装。

**从 1.2.1 升级：**

1. 停服，备份整个 `plugins/SakuraInvite/`，使用 MySQL 时同时导出数据库。
2. 移走旧版 JAR，再放入 1.3.0，避免同时加载两个版本。
3. 保留原配置和数据库。原来用 MySQL 就继续使用 MySQL；更换 `storage` 不会迁移数据。
4. 启动并检查控制台，确认数据库初始化完成。数据库字段会自动升级，发现大小写冲突或更高版本数据库时会停止开放邀请功能。
5. 检查默认邀请人奖励命令是否适合服务器，实际测试一组个人码和一个官方码后再开放。

**旧数据规则：**已有代码、邀请关系和任务记录会保留。旧版没有可靠的剩余库存记录，升级后旧个人码可供新绑定的库存从 0 开始；邀请人使用 `/invite fund` 补充时，先给旧版未预留、未结算的关系补足一份，之后才增加新绑定名额。不会自动生成免费奖励，也不会自动再次扣取旧玩家的钱。

旧版最初收取的资产是否已被使用、旧版“已领取”是否真实到账，无法仅凭旧表可靠还原，需管理员结合旧备份与经济日志核对。已被旧版标记为已领取的记录不会自动再发一遍。

保留现有 `tasks.yml` 时，旧任务名称不会被覆盖；请将 `PLANT` 的“种植”名称调整为“收获成熟作物”，因为新版本按成熟收获计数。已分配任务的文字快照仍可能显示旧名称。

## 玩家使用

### 创建与预存

```text
/invite create
```

上方 45 格是**模板**，不是存放实物的容器：

1. 左键奖励格，复制光标上的物品；光标为空则复制主手物品。
2. 右键清空模板格。多格相同物品会合计扣除，放置模板时留意数量。
3. 点击金锭，在聊天输入每份金币金额，输入 `cancel` 取消金额设置。
4. 确认前把光标物品放回背包。奖励实物必须在背包主存储区，不计盔甲、副手和其他容器。
5. 点击“确认并从背包预存一份”。系统检查物品和余额，扣取一份，随后保存邀请码。

至少设置物品或金币中的一种。每名玩家只拥有一个个人邀请码，创建后每份奖励模板固定，补充时沿用原模板。

例如每份为 **3 个钻石 + 100 金币**，首次创建会收取 3 钻石、100 金币，并获得 1 个可用绑定名额。需要邀请更多人时，先补充对应的奖励。

### 查看、复制、补充和退回

```text
/invite info
/invite fund
/invite withdraw
```

详情界面展示每份奖励、金币和可供新绑定的份数。点击命名牌，在聊天显示可点击复制的邀请码。

`fund` 每次预存一份；系统从背包按固定模板取物，并扣取同额金币。

`withdraw` 每次取回一份**尚未被绑定占用**的奖励，转入自己的待领取列表。已预留给新人的份数不能取回，避免新人完成任务后没有奖励。未预留库存为 0 时不能退回。

### 新人绑定与完成任务

```text
/invite use <实际邀请码>
/invite gui
```

成功绑定时立即预留一份库存，默认分配 3 个随机且不重复的成长任务。不能绑定自己的代码，每名玩家只能绑定一个个人码；当前不提供自行解绑或刷新任务。

任务完成后，系统创建新人奖励和邀请人命令奖励的待发记录。在线且条件满足时自动尝试领取，也可以输入：

```text
/invite claim
```

背包不足时先清理空间；系统不会为此丢掉奖励。邀请人奖励命令会在邀请人在线时发放，因此离线邀请人登录后领取，避免只能对在线玩家生效的命令漏发。

“有效邀请”按全部成长任务完成计数，与外部奖励命令是否执行成功是不同状态。

## 命令和权限

主命令别名：`/si`、`/sakurainvite`。

| 命令 | 功能 | 权限 |
|---|---|---|
| `/invite help` | 帮助 | 所有玩家、控制台 |
| `/invite gui` | 邀请中心、刷新任务、查看关系 | 游戏内玩家 |
| `/invite info` | 自己的邀请码、模板和库存 | 游戏内玩家 |
| `/invite create` | 创建并预存一份 | `sakurainvite.create`，默认 true |
| `/invite fund` | 补充一份 | `sakurainvite.create` |
| `/invite withdraw` | 取回一份未预留库存 | 游戏内玩家，仅自己的库存 |
| `/invite use <码>` | 绑定个人码、兑换官方码 | `sakurainvite.use`，默认 true |
| `/invite claim` | 尝试领取待发奖励 | 游戏内玩家，仅自己的奖励 |
| `/invite records` | 聊天显示最近 10 条记录 | 游戏内玩家 |
| `/invite top`、`/invite rank` | 聊天显示前 10 名，同分并列 | 游戏内玩家 |
| `/invite reload` | 校验并重载配置和任务 | `sakurainvite.reload`，默认 OP |

所有 `admin` 命令需要 `sakurainvite.admin`，默认 OP。配置数据库连接参数后必须重启。

## 官方活动码

```text
/invite admin createofficial SPRING2026
```

创建的是**未发布草稿**，玩家此时不能兑换。管理员在界面复制物品模板、设置金币和命令，保存后输入：

```text
/invite admin limits SPRING2026 100 1440
/invite admin publish SPRING2026
```

例子表示总共 100 个名额，从设置限制的时间起有效 1440 分钟。名额 `0` 表示不限制；分钟 `0` 表示永久。限制按数据库已受理领取人数计算，待领取者也占名额。

```text
/invite admin official
/invite admin editofficial SPRING2026
/invite admin deletecode SPRING2026
```

最后一条是停用，不是删除历史。个人码停用后，已经预留的新人奖励仍会结算。官方码停用后，已生成的待领取奖励也会保留。

官方奖励由服务器发放，模板不会收取管理员物品或金币。命令不带 `/`，支持 `%player_name%` 和 `%code%`，例如 `give %player_name% minecraft:diamond 3`。

代码只能含英文字母、数字、下划线和连字符，长度 3–32；查询、创建和停用使用一致的大小写规则。

## 资金和异常奖励的管理

一般离线、满背包不需要管理员处理，记录保持待领取即可。

如果崩溃发生在“实际扣款/发物品”和“确认写库”之间，无法安全判定所有外部系统是否已完成操作。新版会保留待核对记录，不直接重复发放。

### 奖励发放异常

```text
/invite admin deliveries
/invite admin resolve <编号> retry
/invite admin resolve <编号> complete
```

先核对背包、经济和控制台日志。`complete` 表示确认已到账或已人工处理；`retry` 会重发该条记录的**全部**金币、物品和命令，只有确认这些奖励均未到账、或已人工撤回部分到账内容后才能使用。部分到账时，不要盲目 retry。

### 预存扣取异常

```text
/invite admin funding
/invite admin funding <编号> commit
/invite admin funding <编号> refund
/invite admin funding <编号> items
/invite admin funding <编号> discard
```

| 动作 | 含义 |
|---|---|
| `commit` | 确认物品和金币已收取，继续将一份奖励入库 |
| `refund` | 确认资产已收取，退还整份物品和金币 |
| `items` | 确认只收取了物品、没有扣取金币，仅退物品 |
| `discard` | 确认未扣取资产，或已人工处理，结束该条日志 |

预存日志位于 `plugins/SakuraInvite/funding-journal/`，不要为了消除提示直接删目录。已确定扣款成功但尚未提交数据库的预存，会按操作编号恢复，不重复入库。人工处理会写入控制台审计日志。

## 配置要点

| 配置 | 含义 |
|---|---|
| `storage: sqlite` | 新装默认，本地 SQLite |
| `storage: mysql` | 明确使用 MySQL，连接失败保持功能关闭 |
| `storage: auto` | 旧配置兼容模式，MySQL 连接失败时可按原开关回退；建议确认原数据源后明确指定 |
| `tasks.count` | 新人任务数，1–10，不能超过有效任务池数量 |
| `tasks.progress-save-cooldown-seconds` | 进度合并保存周期，实际限制为 1–30 秒，默认 2 |
| `anti-abuse.max-bindings-per-inviter-ip` | 每名邀请人对同一受邀 IP 的绑定上限，0 不限 |
| `anti-abuse.block-same-ip-as-inviter` | 阻止与建码时邀请人 IP 相同的玩家绑定 |
| `rewards.inviter-commands` | 有效邀请产生的邀请人奖励命令 |

原默认 `points give %player_name% 100` 需要服务器另外安装提供该命令的点券插件。没有点券插件时改为实际可用的命令，或配置 `inviter-commands: []`。

任务仍支持在线、经验等级、击杀、挖掘、成熟作物收获和钓鱼。进度使用合并写入，突然断电可能损失尚未保存的短时间任务进度；奖励库存与领取记录不依赖这些内存进度计数来做重复扣款。

放置方块标记只覆盖安装新版后由玩家事件记录到的放置行为。其他插件直接改世界、既有方块来源及复杂跨服玩法不保证能完全识别。IP 防刷也不能识别所有小号，代理服应先正确转发真实 IP。

## PlaceholderAPI

可用变量：

```text
%sakurainvite_code%
%sakurainvite_inviter%
%sakurainvite_invitees%
%sakurainvite_invitee_names%
%sakurainvite_invitee_1% … %sakurainvite_invitee_20%
%sakurainvite_valid_count%
%sakurainvite_rank%
%sakurainvite_task_progress%
```

数据采用异步缓存，约 5 秒刷新；首次查询可能短暂显示 `...`。

## 验证与运行边界

随包附带构建与自动化测试结果。自动化覆盖金额边界、SQLite 生命周期和迁移、库存预留、重复请求、并发抢库存、官方码名额/过期、异常发奖状态与菜单保护。

仍需在你实际的 Paper 服中验证 Vault/XConomy、CraftEngine 物品及客户端点击体验。MySQL 路径保留并实现行锁，但本轮没有连接真实 MySQL 做集成测试。当前数据库及日志按单个服务端实例使用，不支持多个服同时共享同一插件数据库运行。

本文针对 1.3.0；之前的 1.2.1 说明和审查报告用于记录历史问题，不再作为新版操作说明。
